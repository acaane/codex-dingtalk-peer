# 新联调批次模板

先在对应项目、模块下创建 `YYYYMMDD-YYYYMMDD_主题` 目录，再按总入口的统一目录建立子目录。

- 将 [报告模板](联调记录与总结模板.md) 复制为该批次 `02_过程记录/报告源稿.md`。
- 将 [批次信息模板](批次信息模板.json) 复制为该批次 `批次信息.json`，填写实际项目、模块和基线。
- 正式报告导出为批次根目录 `00_联调记录与总结.docx`，不要把多份阶段小结并列当作最终结论。
- 原始记录按角色、日期和阶段放入 `03_证据`。编号保留原请求或试验身份，人工名称补充用途即可。
- 填写当前模块的双方业务目录、负责人/agent 入口和本次授权范围。其他项目不能沿用已有批次的会话 ID、设备 ID、端口或派单脚本。
- 软件联调、实设备测试和现场验收分别标明；未执行项保留“未验证/暂缓”，注明原因与下一步。
- 结束或中断时登记双方实例、未决请求、资料入口和下一步，更新模块首页及总索引。
