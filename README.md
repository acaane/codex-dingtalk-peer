# AI 联调台

两位同事各自在 Windows 上使用自己的工程助手，在同一个联调窗口查看聊天、任务和回报。项目独立于业务程序运行。Python v1.0 位于 `main`，本项目的开发主线是 `master`。

## 当前可用

打开窗口后在「本机聊天」输入消息并点击「发送」。有效消息保存在当前 Windows 用户的 `%LOCALAPPDATA%\CodexDingTalkPeer\chat.sqlite3`。关闭后重新打开，窗口会恢复本机记录。纯空白输入会收到提示。保存失败时，输入框保留草稿以便重试。

## 内网房间

1. 主协调端点「内网房间」，选择同事能访问的本机 IPv4 地址，点击「创建房间」，复制邀请发给对方。
2. 接入端打开同一个 EXE，在「内网房间」粘贴邀请并点击「加入房间」。复制的邀请限一个接入端，首次加入须在 30 分钟内完成。
3. 双方可以在房间里发送消息。界面显示发送人和主机确认状态。发送未确认时，保留草稿并提供「重试发送」。

连接使用邀请内的主机证书加密。主协调端离开房间或关闭窗口后停止托管。聊天记录保存于主机的 `%LOCALAPPDATA%\CodexDingTalkPeer\rooms`。

双端关闭后，从「内网房间」点「继续上次房间」。主协调端使用原来的内网地址和端口恢复托管，接入端可以先打开并等待主机，双方重新连接后看到原聊天记录。身份和邀请保存在当前 Windows 用户的加密记录里。首次启用续接前创建并关闭的房间只有聊天库，需要新建房间。

要找更早的房间，在「内网房间」点「最近联调」，按本机角色、房间短编号和已绑定的工程目录选择。列表按本机最近打开顺序排列。选中旧房间后会恢复该房间的聊天、会话绑定和任务回报，下次可直接点「继续上次房间」打开它。主协调端可以独自续接并查看主机已保存的记录。

### 收发房间附件

双方使用新版，在房间聊天里点「发送文件」，选择一个最多 5 MiB 的文件。主机保存后，双方可以在附件消息下点「保存文件」，选择保存路径。已有同名文件时，请换一个文件名。

附件和聊天记录一起保留在房间主机上，重新进入同一房间可以再次保存。发送未确认时，同一窗口可以点「重试附件」，继续提交原文件。

### 绑定工程会话

进入房间后，点击「Codex 会话」和「选择工程并绑定」，选择本机工程目录。联调台优先复用该房间已保存的工程会话。首次绑定时，联调台在后台创建并保存专用协调会话。两步均可在 Codex 窗口关闭时完成。

要沿用已有会话的上下文，点「选择已有会话」，选工程目录，再按标题和会话 ID 绑定。绑定只保存在本机，房间续接后可以查看。联调台复用本机已有的 Codex 桌面版或 CLI。

### 双端接单验证

两端都绑定会话后，联调台自动让各自的 Codex 会话在只读模式下回复一次随机校验码。房间顶部显示两端分别在等待、验证、通过或需要处理的状态。只有本轮回合完成且返回正确校验码才算通过。验证失败后，在对应电脑处理提示，再点「重试本端验证」。重开同一房间会恢复已通过的结果。双方使用同一版本验证。

### 派发只读联调任务

双方接单验证通过后，主协调端打开「联调任务」，填写本次要核对的目标和时限，点击「派给接入端（只读）」。接入端的已绑定会话会自动接单。两端可在任务面板查看最新任务的编号、主机截止时间、进度和回报。接入端应保持联调台运行，Codex 窗口可以关闭。

任务在只读模式下执行，每次处理一项。已派发任务随房间续接。接入端离线期间完成的回报先保存在本机，连接恢复后送达。到期前未接单的任务直接结束。执行结果未确认时，界面提示查看接入端原会话，后续续接沿用原任务编号。

在「联调任务」点「任务记录」，可从最新记录逐条翻到较早任务，查看原编号、目标、截止时间及已有回报。点「刷新记录」可重新读取这一条。主协调端可以在接入端退出时查看主机已保存的记录。

### 从主协调端 Codex 会话开始

1. 主协调端在「联调任务」填写目标和时限，点「登记『开始联调』」。
2. 点「复制 agent 启动说明」，把说明粘贴到本房间绑定的主协调端 Codex 会话。收到说明后，这个会话可以在用户明确说「开始联调」时运行启动命令。
3. 保持主协调端房间打开。Codex 收到主机确认后回报任务 ID。两端从「联调任务」查看状态和回报。

要在同一 Codex 会话查看任务，发送「联调进度」或「联调结果」。Codex 查询当前登记对应的任务并转述状态、截止时间和已有回报。查询时保持主协调端房间打开。若会话里已有旧版启动说明，重新复制并粘贴一次。

同一次登记有固定任务 ID。重复告诉 agent 开始联调，或从任务面板提交已登记的相同目标和时限，均会沿用该 ID。需要再执行一次时，重新登记。更换主协调会话后，在当前会话重新登记并粘贴启动说明。移动联调台 EXE 后，从新位置启动联调台并重新复制说明。

## 首版范围

- 主协调电脑在内网托管房间。另一位同事导入邀请，确认本机工程目录并完成 Codex 会话绑定。公司服务器托管作为后续选项。
- 双方绑定后先做一次只读接单和回报。就绪后由发起人对自己的助手下达开始指令，按登记的目标、权限和截止时间推进。窗口显示进度、阻塞和处理人。
- 房间保留聊天、任务和基础文件收发记录。到点写检查点，下次启动可以继续上次联调或打开最近联调。
- 首个试用包覆盖两端内网使用。多人、可选钉钉通道和其他模型适配分别验收。

## 构建与检查

界面采用 GPUI Kit 的默认 GPUI 后端。SQLite 统一使用 SQLx，现有本机聊天库可直接打开。房间通信使用 rustls 加密，依赖版本由 `Cargo.lock` 固定。

在 Windows x64 上打开 Visual Studio Developer PowerShell，使用 Rust MSVC、Windows SDK 和 CMake。

```powershell
cargo fmt --check
cargo test --release --locked
cargo build --release --locked
```

发布构建得到 `target/release/ai-integration-desk.exe`。Windows 交付使用默认动态链接的单 EXE，目标机明确缺运行库时再补。

手动验证时，在本机聊天发送一条含中文和换行的消息，尝试发空白消息，关闭重开后核对历史。房间验证使用两台内网电脑，创建并加入后双向发消息，关闭两端，再先继续接入端、后继续主协调端。核对断线状态、原消息和继续发送，并确认原邀请无法被另一台电脑重复使用。

验证最近联调时，主协调端可以独自创建两个房间，各发一条不同的消息。关闭重开后从「最近联调」打开较早的一项，核对只显示该房间的历史。离开后点「继续上次房间」，应回到刚打开的房间。

验证附件时，两端使用同一新版，续接同一房间。任一端发送一个带中文文件名的测试文件，另一端保存到新路径并核对内容。双端重开后，从原附件消息再保存一次。

验证会话绑定时，保持 Codex 窗口关闭，选一个没有会话的测试工程目录。记下自动绑定的会话 ID，续接房间并再次选同一目录，确认仍是同一个 ID。另可从有历史会话的工程验证「选择已有会话」。

验证接单时，两台电脑各自绑定测试工程与会话。第一端应显示等待，第二端完成绑定后应看到两端分别进入验证。核对双端通过后重开房间，确认仍显示原结果。

验证派单时，可在接入端测试工程里准备一份无敏感内容的文本，再让主协调端派发读取文件首行的只读任务。核对两端任务 ID 相同且主协调端收到正确正文。重开房间后对照原任务 ID 和回报。

验收任务记录可以先续接一个已有任务的房间，再从「联调任务」打开「任务记录」。有多条记录时，翻到较早一条，核对原任务 ID 和正文，再翻回较新一条。主协调端可单人完成这项验收。

验证 agent 启动时，从主协调端的绑定会话发出「开始联调」，核对它回报的任务 ID 与房间一致。再说一次时应返回原 ID。可以从任务面板用相同目标和时限提交，确认仍是同一项任务。

验证 agent 查询时，可以在已登记但尚未启动时问一次「联调进度」，确认仍处于等待开始。再启动任务，等联调台收到接入端回报后，在原会话问「联调结果」，核对任务 ID 和正文。续接同一房间后可查询该登记的回报。
