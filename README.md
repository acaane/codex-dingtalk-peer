# 钉钉 Codex P2P 验证连接器

独立于业务程序运行的 AI 协作连接器。各同事使用自己的 DWS/Codex 登录，通过配置群和自定义 Webhook 机器人交换任务、进度及总结，不依赖公司协调服务器。

本项目负责消息、任务、重试续接、更新和记录；业务源码由对应负责人维护。当前程序已实现 Codex 会话适配，通用说明也可用于其他 AI 工具，但其他工具仍需各自实现和验证适配器。

## 快速开始

1. 将完整部署包解压到独立工具目录，双击 `start.cmd`。
2. 首次选择本人、业务目录、双方约定的项目标识和本人的 Webhook 来源，完成本人 DWS 授权。Codex 使用本人登录或已有模型提供方配置。
3. 出现 `ready` 后可以接任务；窗口保持打开，Ctrl+C 正常停止连接器。
4. 另一台电脑单独登录、配置和启动，不复制 `.local` 或登录数据。

优先复用本机可用的 Python、DWS、Codex，显示实际版本与能力；不强制升级/降级、不卸载、不改全局 PATH。缺少环境时使用包内或本目录 `.tools` 的独立组件。完整 Windows x64 包附带运行时，精简源码包补齐环境需要联网。

部署目录移动后重新运行 `start.cmd` 校准路径。重复启动时，新窗口显示当前实例及最近日志；日志查看窗口 Ctrl+C 只关闭查看，不停止原实例。实例判断依据操作系统文件锁，残留 PID 文字不阻止重启，不要删除运行锁文件。

## 新同事首次接入

所有同事使用同一个通用包和同一套代码。首次启动先复用或准备本机Python/DWS/Codex，再检测本人登录身份、实际群成员ID及已有机器人；身份依据是通讯录userId与真实发送者ID，不按显示名放行，也不创建新机器人。

能够唯一检测的信息自动采用。对端不唯一时显示已有机器人供选择；项目标识和业务目录无法推断时再提示填写。已保存的本人配置优先复用；首次没有本人Webhook时通过已有Excel或隐藏输入提供，并发送一次接入校验消息核实真实机器人发送者。投递未知保留状态，不反复发送。

新部署会从对端真实机器人发给本端的有效接入通知中识别项目；通知不完整、过期或涉及多个项目时提示选择。工具位于业务仓库内，或附近只有一个可识别仓库时可自动采用目录；其余情况仍选择一次。环境与身份核验后自动创建并登记项目专用协调会话，无需另开AI窗口粘贴登记说明；后续启动复用该会话和进度，已有人工登记不被替换。新部署同时启用连接器专用更新，已有明确更新设置保留。

自动创建仅建立本机协调会话，不调用模型、不启动业务程序或设备；收到明确授权任务后沿用原生队列和执行门禁。创建回执不明保留记录，不反复新建。账号默认模型用于首次检查，不再固定优先某个模型；网络检查超时显示中文处理说明。未能确定的项目、目录及本人Webhook仍需本人补充，不能仅凭名称推断或索取同事凭据。

使用 sub2api 等自定义模型提供方时，在本机 Codex 用户级 `config.toml` 选中该提供方，并由本人配置网关凭据。当前提供方不需要 OpenAI 登录时，连接器沿用本机模型配置，通过一次实际调用确认可用。已有部署切换模型提供方后，正常停止连接器并运行 `check.cmd`，通过后再运行 `start.cmd`。[本机配置示例](docs/participant-onboarding.txt)

接入校验会短暂等待群历史同步，仅回读原消息。平台明确拒绝时，修正后运行 `setup.cmd` 可重试一次；回执不明时仍不重发。`collect-group-info.cmd` 可在接入未完成时生成 `group-diagnostics.json`，包含实际 DWS 版本、公开发送能力、群身份和原校验状态，不发送消息、不更改授权或输出凭据。

需要更换本人 Webhook 时运行 `setup.cmd`，在已保存 Webhook 的提示中选 `2=重新粘贴`，只在本机隐藏输入当前完整链接。回车默认复用已保存值，旁边的旧 Excel 不覆盖这个选择。平台返回 `300005 / token is not exist` 时检查当前机器人链接；原接入记录会在凭据更换后保留副本，不必删除 `.local` 或重装登录。

原回执缺少错误详情时，`check-webhook.cmd` 会独立发送一条连接器诊断消息，生成 `webhook-diagnostics.json`。同一凭据的诊断回执不明时，再次运行只核实原诊断消息；明确拒绝并修正后才允许新尝试。实际发送者核实成功后，正常 `setup.cmd` 可复用这份身份证据，原未知消息和未授权配置仍保留。

双击 `start.cmd` 即可首次设置；agent也可在本机执行 `setup_helper.py discover --partner <已有机器人名称> --project-id <双方约定标识>`，再配置本机业务目录。检测结果只保存在各自 `.local`。源码和发行包不附任何同事的私人配置、凭据或项目状态；详细步骤见 [首次接入说明](docs/participant-onboarding.txt)。

## 常用入口

| 入口 | 作用 |
| --- | --- |
| `start.cmd` | 检查环境并启动连接器，已启用更新时同时检查版本 |
| `setup.cmd` | 重新配置本人、业务目录和机器人 |
| `check.cmd` | 校验账号、群身份及一次小规模 Codex 调用 |
| `task.cmd` | 从本机向对端发起任务 |
| `resume.cmd` | 按已保存进度继续或建立关联任务 |
| `stop-task.cmd` | 停止指定任务 |
| `enable-auto-update.cmd` | 启用更新接收并通过监护器启动 |
| `publish-update.cmd` | 手动发布当前连接器白名单代码 |
| `collect-group-info.cmd` | 只读采集当前群身份诊断 |
| `check-webhook.cmd` | 一次独立发送检查，保存脱敏回执并核实实际机器人 |
| `collect-event-info.cmd` | 只读采集监听/总线诊断 |
| `recover-event-bus.cmd` | 通过安全门禁后处理旧总线 PID |

命令行示例：

```powershell
python peer.py --config .local/config.json --peer A run
python peer.py --config .local/config.json --peer A status
python peer.py --config .local/config.json --peer A start --to B --goal '仅核对接口定义并列出差异'
python peer.py --config .local/config.json --peer A resume --task <任务编号> --to B
```

双方使用不同本人账号启动后，配置中的主人也可在群里发送：

```text
AI联调 项目 project-alpha 开始 请双方核对接口字段，列出差异并结束。
AI联调 项目 project-alpha 停止 <12位任务编号>
AI联调 项目 project-alpha 继续 <12位任务编号> <可选新目标>
```

DWS 不推送当前登录用户自己发送的自然人消息，由另一台电脑按主人身份转发。单机同账号模拟使用本地 `task.cmd`，不要把模拟成功当成真实业务通过。

## 协调 agent 与业务边界

通用启动说明见 [coordinator-start.txt](docs/coordinator-start.txt)。每个项目分别填写角色、业务目录、接口、权限、截止时间和负责人入口，不沿用其他项目的设备 ID 或会话。

新部署默认自动建立协调会话（`auto_coordinate=true`），记录保存在当前项目的 `.local/projects/<项目标识>/business-agent-<端ID>.json`。也可在原业务协调会话执行 `setup_helper.py register-agent`，读取自身 `CODEX_THREAD_ID` 登记；已有绑定优先保留。派单通过本机实际支持的 `codex queue` 投递给该项目已绑定会话；双端实际派单、处理和回传已验证。自动首次建会话已完成本地回归，新的双机首次接入仍须实际核验。其他工具的通用职责说明不代表其适配器已实现。

主协调端示例：

```powershell
python peer.py --config .local/config.json --peer A business-handoff --to B --message-file <任务文件> --expires-at <截止Unix秒>
python peer.py --config .local/config.json --peer A business-status
python peer.py --config .local/config.json --peer A business-health --to B
```

队列回执只证明消息已入队；业务会话写回 `in_progress` 才能确认已开始处理。长时间只有入队回执时，`business-health` 让对端连接器直接读取已绑定会话的队列元数据和 Codex 后台健康状态，不需要先启动业务 agent，也不重复投递原任务。诊断按真实机器人、项目及绑定会话授权，不返回消息正文或账号凭据；不在队列中也不能单独证明业务已经执行。

连接器自动检测本机入口，CLI优先；两者都有时默认CLI，只有已注册的桌面入口时才用App。确认原消息仍在队列后，CLI后台消费原会话的原队列；App请求打开原会话。不新建聊天、不另发提示词、不代点确认，不改全局后台配置或工具版本。CLI后台只消费本项目已授权消息，遇到未结束回合、其他来源队首、交互审批或不支持的接口时报告原因并保留状态。每组原队列只尝试一次，重启不重复唤醒；启动请求不等于业务已执行。

CLI宿主在本轮有效期内保持在线，消息已被原生队列取走时仍等待回合与业务回报，不以“队列为空”关闭宿主。原生恢复会话自行开始的回合也会等待完成；连接器更新不关闭这个独立宿主。业务负责人须按本轮截止安排程序正常退出，原会话在宿主结束前由后台托管。

恢复原会话前，宿主先有界分页核对整个原生队列，并重新检查项目绑定、截止时间及已保存的开始尝试。仅对能同时核实本项目、原协调方、原会话、原排队ID、已过期时间及原始文件引用/SHA的连接器消息，撤销其待执行项；每次最多8项，原文、任务库和撤销记录保留。撤销前后重新读取，回执不明不重复撤销。其它未授权、开始结果不明、原文不符或队列读取不完整的情况保留队列并报告阻塞，不调用恢复或开始接口。已有明确拒绝证据的兼容恢复继续遵守原有有界规则。这可防止原生恢复自动取队列时绕过连接器的检查，不代表任意外部宿主或并发队列变化都已验证。

CLI回合结束状态另存本项目`business-consumers/turn-<队列ID>.json`。消息离队仍无业务回报时，`business-health`按精确开始回执或本任务文件SHA核对最近回合、回报文件格式，并给出有界脱敏的末尾回复；不回传输入正文或凭据。已有App/CLI宿主接走的本连接器任务也能据此核对。回合完成不代表业务联调完成。原生接口明确拒绝的兼容恢复保留前次证据并有界处理，未知开始回执不重试。

宿主退出诊断会保留上次失败状态，并仅返回当前绑定及所查请求的脱敏原因、Python异常类型和连接器源码行号；原始stderr留在本端runtime。原生只读历史可能把仍在写入的回合暂示interrupted，应结合宿主锁、响应文件和真实业务日志判断。Windows状态文件遇短暂共享占用会有界等待，永久失败仍保留旧完整文件。

普通接口核对默认只读。业务修改、启动或设备操作按当前明确授权交对应负责人；连接器监护器只管理自己创建的连接器进程，不自动重启业务程序。

## 重试、离线与次日继续

各项目的 `runtime/<端ID>/projects/<项目标识>/state.sqlite3` 保存目标、已处理消息、待办、模型结果、发送状态和同步位置，不能删作缓存或交给同事复用。

- 模型超时、容量及明确临时网络错误，默认最多重试 3 次，间隔从 15 秒增加、上限 300 秒。账号、权限、配置或输出格式错误保留状态，处理后再继续。
- 结果先落盘再发送。只有明确可重试的拒绝才重试；回执不明记作 `delivery_unknown`，从真实发送者的群历史核实，不盲目重发。
- 监听断开有界重连；重启补收协议消息，先处理完成/停止，不重放旧的自然人“开始”指令。历史读取不完整时保留位置并提示。
- `ready` 前订阅失败遵守 DWS 的 retryable、等待及保护状态。明确不可重试不重试，不清空订阅保护；详情见 `listener-startup-error.json`。
- 等待对端超过 15 分钟转 `waiting_peer`，进度不丢。次日双方启动后恢复未完成待办；已完成任务通过继续入口建立关联任务，保留旧终态。

任务最多 6 轮，单次模型调用默认 75 秒，可通过配置调整。已经结束的旧消息不会再次触发模型。

## 更换联调项目

1. 正常停止本机连接器，运行 `setup.cmd`，选择新的业务目录和项目标识。新项目必须填写标识，例如 `project-alpha`；双方使用相同标识，取值为1至64位小写字母、数字、下划线或连字符。
2. 新配置自动建立该项目的协调会话，或在原业务协调 agent 会话中登记。新项目不会继承其他项目的 agent、未完成任务或 `latest` 续接记录。
3. 用 `task.cmd` 发起新任务；群指令明确写项目，例如 `AI联调 项目 project-alpha 开始 核对接口`、`AI联调 项目 project-alpha 继续 <任务编号>`。

项目配置保存在 `.local/projects/<项目标识>/config.json`；`.local/config.json` 是当前选中的配置。重新选择已有标识和原目录可使用其保存的项目记录。更改同一标识的工作目录时，已有任务库会拒绝混用；为不同目录的独立工作建立新标识。

一个安装目录的同一端只运行一个连接器，实例锁、更新和连接器日志仍共用；任务库、业务派单文件、总结和 agent 绑定按项目隔离。现有无 `project_id` 的旧部署保留原 `runtime/<端ID>` 和 `.local/business-agent-<端ID>.json`，不自动迁移或删除，群指令也沿用无项目标识的原格式。同一业务工程的独立模块可使用不同项目标识。新配置不再提供任何具体业务工程默认路径；业务端口、协议和负责人入口来自各项目资料。

## 自动更新

启用后，发布端在启动及运行期间检查白名单代码。文件稳定约 30 秒后实际执行语法、编码和本地单元测试；通过后才发布，变化中的文件重新等待。同版本不重复发布，相邻发布至少间隔 5 分钟；默认由配置中 ID 最小的一端发布，当前为 A。

接收端在启动后的首次历史同步结束后检查已发布版本。更新经已有机器人分片传送，校验真实发布身份、白名单、大小和 SHA-256 后安装，由监护器重启；90 秒未就绪或启动失败时回退。控制台分别显示开始传输、传输结束、开始安装、重启就绪和对端确认，不能把传输完成当作安装成功。

A 离线或检查失败时继续当前版本。发送未知、发布中断、已回退的失败版本不自动重复发布，先核实投递。状态与已发布原包保存在 `.local`，属于有效运行/恢复数据。将 `.local/update-policy.json` 的 `auto_publish` 设为 `false` 可暂停自动发布，接收与手动入口保留。

更新只覆盖 `connector_update.ALLOWED`，不覆盖 `AGENTS.md`、私人配置、登录、工具运行时或业务项目。直接执行 `peer.py run` 只暂存更新，自动替换与重启需要 `start.cmd` 外层监护器。旧版升级说明见 [connector-recovery-update.txt](docs/connector-recovery-update.txt)。

## 记录、总结与资料组织

完成、停止、中断、重试耗尽或长时间等待时，各端根据已存记录生成中文总结，输出窗口、保存当前项目任务目录下的 `summaries/<报告编号>.txt` 并发配置群，不依赖额外模型调用。中断后另一端补充自身进度，不循环触发。更新重启不当成业务中断；突然断电或离线后在下次启动补报。相同报告去重，未知发送先核实。`task_summaries=false` 可关闭自动总结。

业务正式资料从 [联调资料总入口](联调资料/README.md) 查找，按项目、模块、日期批次存放完整 Word 报告、原始证据及索引。机器人状态、工具和账号资料与业务资料分开；历史兼容路径不可当作重复数据递归清除。具体项目数据不进入 Git 或发行包，规范、模板及通用导出工具可版本管理。

具体业务的当前阶段、接口、地址、程序和结果仅记录在各项目资料中；通用入口不自动选取历史项目或重启旧试验。每日未完成联调默认北京时间 17:35 开始收尾，策略见 `integration-policy.json`，任务有明确要求时按当前授权执行。

## 诊断与保留范围

登录与群身份修复已包含当前源码；历史 `login-hotfix`、`group-identity-hotfix` 独立补丁已停用。登录失败重新运行 `setup.cmd`；身份诊断使用 `collect-group-info.cmd`，只提交生成的诊断 JSON，不提交 `.local`。

`discover bus`、`bus child startup failure` 且未 ready 时，消息通道尚未启动。先正常停止失败监听，运行 `collect-event-info.cmd` 生成脱敏 JSON。恢复入口先核同一 profile、路径、无活动订阅/进程，再取得 DWS 实际文件锁并确认 PID 未变，才清空旧 PID；保留原锁、登录和保护数据。门禁不满足就停止，不凭错误码杀共享进程或重置账号。

本版使用个人 DWS 监听及群自定义 Webhook，沿用现有账号；不采用企业应用发布/审批路线。消息身份按真实发送者 ID 校验，不按名称或正文 A/B 授权。Webhook 通过 Windows DPAPI 保存，只支持当前实现验证的关键词 URL；不把令牌放进提示、日志或发布包。三端以上协作、其他 AI 适配器、消息撤回及现场设备验收尚未作为本工程通用能力验证。
