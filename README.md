# AI 联调台

两位同事各自在 Windows 上使用自己的工程助手，在同一个联调窗口查看聊天、任务和回报。项目独立于业务程序运行。Python v1.0 位于 `main`，本项目的开发主线是 `master`。

## 当前可用

打开窗口后在「本机聊天」输入消息并点击「发送」。有效消息保存在当前 Windows 用户的 `%LOCALAPPDATA%\CodexDingTalkPeer\chat.sqlite3`。关闭后重新打开，窗口会恢复本机记录。纯空白输入会收到提示。保存失败时，输入框保留草稿以便重试。

## 内网房间

1. 主协调端点「内网房间」，选择同事能访问的本机 IPv4 地址，点击「创建房间」，复制邀请发给对方。
2. 接入端打开同一个 EXE，在「内网房间」粘贴邀请并点击「加入房间」。复制的邀请限一个接入端，首次加入须在 30 分钟内完成。
3. 双方可以在房间里发送消息。界面显示发送人和主机确认状态。发送未确认时，保留草稿并提供「重试发送」。

连接使用邀请内的主机证书加密。主协调端离开房间或关闭窗口后停止托管。聊天记录保存于主机的 `%LOCALAPPDATA%\CodexDingTalkPeer\rooms`。

双端关闭后，从「内网房间」点「继续上次房间」。主协调端使用原来的内网地址和端口恢复托管，接入端可以先打开并等待主机，双方重新连接后看到原聊天记录。身份和邀请保存在当前 Windows 用户的加密记录里。首次启用续接前创建并关闭的房间只有聊天库，需要新建房间。

### 绑定工程会话

进入房间后，点击「Codex 会话」和「选择工程并绑定」，选择本机工程目录。联调台优先复用该房间已保存的工程会话。首次绑定时，联调台在后台创建并保存专用协调会话。两步均可在 Codex 窗口关闭时完成。

要沿用已有会话的上下文，点「选择已有会话」，选工程目录，再按标题和会话 ID 绑定。绑定只保存在本机，房间续接后可以查看。联调台复用本机已有的 Codex 桌面版或 CLI。创建会话阶段只保存会话和绑定，两端接单验证和任务执行属于后续阶段。

## 首版范围

- 主协调电脑在内网托管房间。另一位同事导入邀请，确认本机工程目录并完成 Codex 会话绑定。公司服务器托管作为后续选项。
- 双方绑定后先做一次只读接单和回报。就绪后由发起人对自己的助手下达开始指令，按登记的目标、权限和截止时间推进。窗口显示进度、阻塞和处理人。
- 房间保留聊天、任务和基础文件收发记录。到点写检查点，下次启动可以继续上次联调或打开最近联调。
- 首个试用包覆盖两端内网使用。多人、可选钉钉通道和其他模型适配分别验收。

## 构建与检查

界面采用 GPUI Kit 的默认 GPUI 后端。SQLite 统一使用 SQLx，现有本机聊天库可直接打开。房间通信使用 rustls 加密，依赖版本由 `Cargo.lock` 固定。

在 Windows x64 上打开 Visual Studio Developer PowerShell，使用 Rust MSVC、Windows SDK 和 CMake。

```powershell
cargo fmt --check
cargo test --release --locked
cargo build --release --locked
```

发布构建得到 `target/release/ai-integration-desk.exe`。Windows 交付使用默认动态链接的单 EXE，目标机明确缺运行库时再补。

手动验证时，在本机聊天发送一条含中文和换行的消息，尝试发空白消息，关闭重开后核对历史。房间验证使用两台内网电脑，创建并加入后双向发消息，关闭两端，再先继续接入端、后继续主协调端。核对断线状态、原消息和继续发送，并确认原邀请无法被另一台电脑重复使用。

验证会话绑定时，保持 Codex 窗口关闭，选一个没有会话的测试工程目录。记下自动绑定的会话 ID，续接房间并再次选同一目录，确认仍是同一个 ID。另可从有历史会话的工程验证「选择已有会话」。
